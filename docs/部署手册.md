# 部署手册 — 合同审批审查 Agent（云端生产）

> 目标环境：独立云服务器（与项目 A 物理隔离）。
> LLM 推理默认走**智谱 BigModel OpenAI 兼容端点（GLM glm-5.3-flash）**，仅依赖出网 HTTPS；
> 本地 GPU vLLM 为备选路径。**零降级铁律：LLM 不可达时审查任务显式
> blocked（人话原因），系统健康面如实报 llm 异常——绝不产出伪造审查结果。**

## 1. 服务器选型与初始化

| 项 | 建议值 |
|----|--------|
| 厂商 | 腾讯云 / 阿里云均可 |
| 规格 | 2核4G 起；系统盘 40G+ |
| 系统 | Ubuntu 22.04 LTS |
| 安全组 | 放行 `22/tcp`（限本人 IP 更佳）与 `18000/tcp`；**其余全部拒绝** |
| 带宽 | 5M 固定或按流量（附件 KB 级） |

```bash
sudo apt update && sudo apt -y upgrade
sudo apt -y install git curl ufw
sudo ufw allow 22/tcp && sudo ufw allow 18000/tcp && sudo ufw enable
```

## 2. 安装 Docker（国内源）

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER   # 重新登录生效
```

## 3. 拉取代码与配置

```bash
sudo mkdir -p /opt && cd /opt
sudo git clone https://github.com/nobodycare-no/contract-review-agent.git
cd contract-review-agent

cp deploy/.env.example .env
vim .env    # 必改：ADMIN_TOKEN / DB_ROOT_PASSWORD / LLM_API_KEY（智谱 BigModel APIKey）
```

## 4. 生产启动（override 叠加）

```bash
cd /opt/contract-review-agent/deploy
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

- 双容器：mysql + app（TZ=Asia/Shanghai，落库即中国时间）
- prod override：全服务 restart 策略；app `18000:8000` 对外；MySQL 无宿主端口；命名卷持久化

## 5. LLM 接入（BigModel GLM，零降级前提）

1. `.env` 填 `LLM_API_KEY`（智谱开放平台 APIKey）→ `docker compose restart app`
2. `GET /app/diag_llm` 返回 `status=200` 且 `reply` 非空即链路通
3. `GET /health` 的 `llm.ok=true` 即接入成功
4. **LLM 故障时**：审查任务会 blocked，原因注明运行失败——恢复后详情页
   「重新处理此单」一键重跑（GLM 真机 2.5~4.5 分钟/张，模型逐轮检索原文核实）
5. 可选调优：`LLM_THINKING=low`（Agent 思考档位 low/high/max；默认重思考更慢但更深）；
   `AGENT_MAX_STEPS=20`（步数预算，GLM 部署调优值）
6. 本地 GPU 备选：按 **deploy/GPU_VLLM_START.md** 启动 vLLM（必须含
   `--enable-auto-tool-choice --tool-call-parser hermes`），改 `.env` 三项 LLM_* 即切换

## 6. 验收探针（V2，11 项）

```bash
# 宿主机（已装 python3+httpx）：
APP_URL=http://127.0.0.1:18000 python backend/app/acceptance/probe.py
```

⚠ 探针会 **reset-demo 重种演示单**（清空现有业务数据），生产环境慎跑。
浏览器验收：`http://<公网IP>:18000/` → 上传合同 → AI 审查 → 详情页留痕时间线/原件查看/服务端耗时。

## 7. 数据备份与运维

```bash
# 每日备份（crontab 凌晨3点）
0 3 * * * cd /opt/contract-review-agent/deploy && \
  docker compose exec mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" contract_review' \
  > /opt/backups/cra_$(date +\%F).sql

docker compose logs -f app --tail=200    # 实时日志（uvicorn/uvloop 双 worker）
```

升级流程：`git pull` → `docker compose ... up -d --build` → 重跑探针。

## 8. 与项目 A 的隔离声明

独立仓库、独立 compose 项目名（contract-review-agent）、独立网络（cranet）与数据卷；
宿主端口 18000 与 A 的 8081/13306/19530 无交集。本手册所有命令均在 B 自身目录内执行。
