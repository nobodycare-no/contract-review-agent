# 云端部署手册 — 合同审批审查 Agent · GLM 云端 API 版

> **本手册属于分支 `feat/cloud-glm53flash`（GLM 云端 API 版），独立自包含**：
> 不需要 GPU、不需要 AutoDL，一台普通云服务器 + 一个智谱 APIKey 就能跑。
> 写法：每一步都是完整命令，**一行一行复制粘贴**即可复现；每步末尾有「✅ 自检」，
> 看到预期输出再往下走。卡住直接翻文末《故障速查表》。
>
> **机器标记**：【本机】=你自己的电脑（Windows PowerShell）；【服务器】=云服务器。
> 命令默认在【服务器】上执行。
>
> 零降级铁律：LLM 不可达时审查任务显式 blocked（人话原因），绝不产出伪造审查结果。

---

## 第 0 步：准备清单

| # | 东西 | 去哪拿 |
|---|------|--------|
| 1 | 云服务器一台 | 腾讯云/阿里云轻量或 ECS，**2核4G 起**，系统 **Ubuntu 22.04** |
| 2 | 服务器公网 IP + SSH 密码 | 购买页/控制台 |
| 3 | 智谱 APIKey | https://open.bigmodel.cn → 注册 → 控制台 → API Keys → 复制 |

> GPU 本地模型部署是另一个分支（`feat/langchain-react-gpu-only`）的事，有它自己的手册，
> 与本手册互不相干、互不依赖。

---

## 第 1 步：【本机】云控制台放行端口

安全组/防火墙添加两条入站规则：

| 协议 | 端口 | 来源 |
|------|------|------|
| TCP | 22 | 你的 IP（或 0.0.0.0/0） |
| TCP | 18000 | 0.0.0.0/0 |

✅ 自检：本机 PowerShell 敲 `ssh root@<服务器IP>` 能登录（第一次输 `yes` 再输密码）。

---

## 第 2 步：【服务器】系统初始化

```bash
sudo apt update
sudo apt -y upgrade
sudo apt -y install git curl ufw nano
sudo ufw allow 22/tcp
sudo ufw allow 18000/tcp
sudo ufw --force enable
```

✅ 自检：`sudo ufw status` 里 22 和 18000 都是 ALLOW。

---

## 第 3 步：【服务器】安装 Docker

云服务器在国内时 `get.docker.com` 直连经常被墙，**直接用腾讯内网源**（阿里云把
`mirrors.cloud.tencent.com` 换成 `mirrors.aliyun.com` 即可）：

```bash
sudo apt -y install ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt -y install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
```

再配镜像加速（否则下一步拉基础镜像会很慢）：

```bash
sudo tee /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com"] }
EOF
sudo systemctl restart docker
```

✅ 自检：`sudo docker compose version` 显示 `v2.x`；`sudo docker info | grep -A1 "Registry Mirrors"` 能看到加速地址。

## 第 4 步：拿代码到服务器（两种方式选一）

### 方式 A（能访问 GitHub 时最简单）【服务器】

```bash
sudo mkdir -p /opt && cd /opt
sudo git clone https://github.com/nobodycare-no/contract-review-agent.git contract-review-agent
cd contract-review-agent
git checkout feat/cloud-glm53flash
```
> 提示输密码 = 仓库私有：用户名填 GitHub 用户名，密码填 Personal Access Token
> （GitHub → Settings → Developer settings → Tokens，勾 repo 权限）。

### 方式 B（GitHub 连不上时的稳妥方案）【本机 + 服务器】

```powershell
cd D:\260525\phase9_vibecoding\project\contract-review-agent-glm
git bundle create D:\cra-glm.bundle feat/cloud-glm53flash
scp D:\cra-glm.bundle root@<服务器IP>:/opt/
```
✅ scp 末尾显示 `100%`。然后到【服务器】：

```bash
sudo mkdir -p /opt && cd /opt
sudo git clone /opt/cra-glm.bundle -b feat/cloud-glm53flash contract-review-agent
cd contract-review-agent
```

✅ 自检：`git log --oneline -1` 显示 `75de314` 或更新（docs(cloud) 开头的提交）。

## 第 5 步：【服务器】写配置文件 .env

```bash
cd /opt/contract-review-agent
cp deploy/.env.example .env
nano .env
```

把 `LLM_API_KEY=` 一行改成你的智谱 APIKey，`ADMIN_TOKEN=` 改成你自己编的管理口令，
其余保持不动。改完：**Ctrl+O → 回车 → Ctrl+X** 保存退出。

改完应长这样（关键的 7 行）：

```bash
ADMIN_TOKEN=你自己编的管理口令
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_API_KEY=你的智谱APIKey
LLM_MODEL=glm-5.3-flash
LLM_THINKING=low
LLM_TIMEOUT_S=120
AGENT_MAX_STEPS=20
```

✅ 自检：`grep -E "LLM_MODEL|LLM_API_KEY" .env` 显示的模型是 `glm-5.3-flash`、Key 非占位符。

## 第 6 步：【服务器】启动（首次构建约 5~15 分钟，只是等）

```bash
cd /opt/contract-review-agent/deploy
sudo docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

> 过程中自动装依赖（pip 清华源、npm 国内源）；网络抖动报错就**原样重跑同一条命令**续上。

✅ 自检：`sudo docker compose ps` —— `app` 和 `mysql` 两行都是 `Up`（mysql 带 `(healthy)`）。

---

## 第 7 步：【服务器】验证

```bash
curl -s http://127.0.0.1:18000/health
```
✅ 预期：`{"status":"ok","components":{"mysql":{"ok":true,...},"llm":{"ok":true,...}}}`

```bash
curl -s -X GET http://127.0.0.1:18000/app/diag_llm
```
✅ 预期：`"status":200,"reply":"在线"` ——这就是 BigModel GLM 真实回话的证据。

【本机】浏览器打开 **http://<服务器IP>:18000** ——能看到审批工作台即部署完成。

## 第 8 步：【服务器】11 项验收探针（可选）

```bash
cd /opt/contract-review-agent/deploy && sudo docker compose exec app python -m app.acceptance.probe
```
✅ 预期末行：`==== 探针汇总：11/11 PASS ====`
（其中 AGENT-RUN 会真实调一次 GLM 跑完整审查闭环，约 3~5 分钟，属正常耗时。）

> ⚠ 探针会 **reset-demo 重置演示数据**（清空业务数据、重种 5 张标准演示合同）。

---

## 第 9 步：【本机浏览器】一次跑所有合同

1. 打开 `http://<服务器IP>:18000`
2. 需要恢复初始演示状态时，【服务器】敲：
   ```bash
   curl -s -X POST http://127.0.0.1:18000/admin/reset-demo -H "X-Admin-Token: 你的ADMIN_TOKEN"
   ```
3. 首页**全选** 5 张单 → 点「开始批量自动审查」→ 随便刷新页面，跟踪不丢
4. 每张约 3~5 分钟（GLM 逐轮思考+检索原文核实），全部变「已完成」后逐单检查：
   - 合同基本信息（含「AI 核对」标记）
   - 风险条目 + 审查意见全文（首行「总风险等级：…」）
   - **留痕时间线**（每轮工具调用带时间戳；你会看到多次 search_contract_text——
     模型在回原文逐条核对，这正是选 GLM 抗幻觉的意义）
   - 「查看原件」能打开合同原文

✅ 自检：5 张全部「已完成/已写入评论区」，时间线里 `write_approval_comment → ok`。

## 故障速查表

| 症状 | 原因 | 处理 |
|------|------|------|
| 浏览器打不开 :18000 | 端口没放行 | 云安全组 + ufw 都要有 18000 |
| health 里 `llm.ok=false` | Key/网络问题 | 先看下一条 diag_llm |
| diag_llm 返回 401 | APIKey 错 | 回第 5 步核对 Key；改完 `restart app` |
| diag_llm 超时/连不上 | 服务器出网被墙 | 检查云厂商出网限制/给服务器配代理 |
| diag_llm 返回 429/额度类错误 | 智谱账户欠费或限流 | open.bigmodel.cn 控制台充值/看额度 |
| 审查单变「需人工处理」，原因含 `LLM_RUN_FAILED` | 运行中网络抖动 | 详情页点「重新处理此单」即可重跑 |
| clone 提示输密码一直失败 | 仓库私有 | 密码处填 Personal Access Token，不是 GitHub 登录密码 |
| 审查结论每次略有差异 | 大模型本质（温度 0.2 非确定性） | 特性非缺陷，结论通常收敛在同一风险级 |

## 附：与 GPU 版的关系

- 本分支 = GLM 云端 API 版（本手册）；`feat/langchain-react-gpu-only` = 本地 GPU vLLM 版（另有手册）。
- 两分支代码同源、数据库结构相同；切换版本 = 切分支 + 改 `.env` 的 `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL` + `up -d --build`，代码零改动。
