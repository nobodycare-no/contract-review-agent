## 1. 引擎

- `AGENT_ENGINE` 默认 `langchain`；`legacy` 开关仅保留对比能力（单测经 conftest 强制 legacy 隔离）。
- LangChain 官方 `create_agent`（底层 LangGraph）：`backend/app/services/lc_agent.py`。
- `ChatOpenAI` → 智谱 BigModel OpenAI 兼容端点原生 tools（`zai-custom` · `glm-5.3-flash`，
  密钥走 `.env` 的 `LLM_API_KEY`，不进代码）；步数预算=recursion_limit（agent_max_steps×2，
  本分支部署值 `AGENT_MAX_STEPS=20`——GLM 决策更缜密，规范缺省 12 不够闭环，真机实证）。
- **模型特性（真机实证）**：glm-5.3-flash 始终思考（不支持关闭，`{"type":"disabled"}` 400；
  默认重思考≈19s/轮）——`LLM_THINKING=low` 经 `extra_body` 仅作用于 Agent 主线，轮耗时降至≈8s；
  AI 审查层不带该参数（无 tools 请求同参数 400），默认思考 + `max_tokens 3000` 保证 JSON 完整。
- **并行工具调用串行化**：GLM 一条消息可并行发多个工具调用，LangGraph ToolNode 多线程执行，
  共享 Session 并发使用即崩（`provisioning a new connection`，真机实证）——
  全部工具调用经 `RunContext.serial_lock` 串行化。
- **零降级铁律**：LLM 不可用/超时/闭环未完成 → 异常上抛 → API 502 → 任务 `blocked`。
  v1.x 的确定性通道/熔断器/JSON 协议降级在本分支一律不存在。

## 3. 闭环与韧性语义

- **闭环闸门**：`run_lc` 返回前验证——正式运行须 `ctx.written`（意见真实写回）；
  dry-run 须已保存结果。不满足 → RuntimeError（**异常携带完整 `.trace`**，失败轨迹同样
  落库 `task_logs`，根因可诊断）→ 502 → blocked。
- **工具包络韧性**：非 ToolError 异常先 `db.rollback()`（防 flush 失败毒化会话传染后续
  工具的 Doom-loop，真机实证）再回填真实原因给模型自纠。
- **自动纠偏轮**：已保存未写回时，追加一轮显式指令让模型补写（仍由模型决策，轨迹记账）。
- **重试=真跑引擎**：`POST /agent/tasks/{id}/retry` 复位后同步执行完整闭环；
  `/agent/run` 与批量工人对 blocked/done 单先复位再进引擎。
- **同单互斥**：`engine.try_acquire`；第二请求 409「正在审查中」。
- **启动/批量自愈**：parsing/reviewing 孤儿 → blocked，原因只陈述事实
  （「上次运行未完成……可能因进程重启或运行中断」），不虚构成因。
- **诚实计时**：响应 `elapsed_ms` = `agent.invoke` 真实墙钟。

## 4. 状态机增量（相对 §2.4.4）

- `done → parsing`：再次审查（一键复检）；
- `blocked → parsing`：由 retry_task 完成（缺附件 409 人话拒绝）；
- 自愈原因文案见上；UI 将 parsing/reviewing 合并呈现为「AI 审查中」（工程状态保留）。

## 6. 遗留与偏差登记

- `agent_runs` 表仅 legacy 车道写入；LC 车道留痕走 `task_logs(type=tool)` + `run_trace`。
- 历史数据的 `created_at` 为 UTC（TZ 修复前落库），新数据为中国时间。
- 提示词/工具/引擎全部模型无关：换 OpenAI 兼容模型仅需改 `.env` 的
  `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL`；本地 GPU vLLM 备选路径见 `deploy/GPU_VLLM_START.md`。
