# V2 分支现状（行为权威文档）

> 分支 `feat/langchain-react-gpu-only`。本文描述**实际运行行为**；SRD/SAD/SDD/两手册
> 描述 main v1.x 基线，凡与本文冲突处以本文为准。最后核对：2026-08-28，87 passed / 2 skipped。

## 1. 引擎

- `AGENT_ENGINE` 默认 `langchain`；`legacy` 开关仅保留对比能力（单测经 conftest 强制 legacy 隔离）。
- LangChain 官方 `create_agent`（底层 LangGraph）：`backend/app/services/lc_agent.py`。
- `ChatOpenAI` → vLLM OpenAI 兼容端点原生 tools；步数预算=recursion_limit（agent_max_steps×2）。
- **零降级铁律**：LLM 不可用/超时/闭环未完成 → 异常上抛 → API 502 → 任务 `blocked`。
  v1.x 的确定性通道/熔断器/JSON 协议降级在本分支一律不存在。

## 3. 闭环与韧性语义

- **闭环闸门**：`run_lc` 返回前验证——正式运行须 `ctx.written`（意见真实写回）；
  dry-run 须已保存结果。不满足 → RuntimeError（附轨迹尾部）→ 502 → blocked。
- **自动纠偏轮**：已保存未写回时，追加一轮显式指令让模型补写（仍由模型决策，轨迹记账）。
- **重试=真跑引擎**：`POST /agent/tasks/{id}/retry` 复位后同步执行完整闭环；
  `/agent/run` 与批量工人对 blocked/done 单先复位再进引擎。
- **同单互斥**：`engine.try_acquire`；第二请求 409「正在审查中」。
- **启动/批量自愈**：parsing/reviewing 孤儿 → blocked，原因只陈述事实
  （「上次运行未完成……可能因进程重启或运行中断」），不虚构成因。
- **诚实计时**：响应 `elapsed_ms` = `agent.invoke` 真实墙钟。

## 4. 状态机增量（相对 §2.4.4）

- `done → parsing`：再次审查（一键复检）；
- `blocked → parsing`：由 retry_task 完成（缺附件 409 人话拒绝）；
- 自愈原因文案见上；UI 将 parsing/reviewing 合并呈现为「AI 审查中」（工程状态保留）。
