## 四、实现偏差披露（与规范显式取舍）

| 偏差 | 规范原文 | 实现取值 | 理由 |
|------|---------|---------|------|
| 工具签名 ctx 化 | §2.4.10 instance_id/document_id/case_id 形参 | schema 只声明 dispatch 真实消费参数 | 防 AI 编造假参数（schema 债清偿） |
| 工具扩至十个 | §2.4.10 七工具 | +submit_basic_info/search_contract_text/list_review_rules | AI 以原文修正解析；小上下文检索通道；规则库可查 |
| 审批系统为本地域 | 外部审批系统 | V1 起 mock 物理删除，自有业务表承载 | 统一系统语义；回写=真实业务写入 |
| 第九表 agent_runs | 八表之外 | 保留但仅 legacy 车道写入 | LC 车道留痕走 task_logs(type=tool) |
| 零降级 | （规范未要求降级） | **废除** v1.x 的确定性通道/熔断/JSON 协议 | 假成功摧毁信任；失败必须诚实 |
| done 可复检 | §2.4.4 未定义 done 出边 | done→parsing | 合同改版复检是刚需 |
| 重试语义升级 | blocked 重试回 parsing | 重试=复位+同步真跑引擎 | 统一系统无后台轮询工人，复位不跑=悬置 |
| 批量账本/elapsed_ms/互斥锁 | 未要求 | 新增 | 消灭「前端说完毕 GPU 还在跑」类体验裂隙 |
| TZ=Asia/Shanghai | 未要求 | compose 环境注入 | 审查留痕必须本地时区 |

## 五、结论

§2.4 全部验收标准在真实栈取证通过；在此之上，V2 以「零降级 + 闭环闸门 + 真实耗时 +
工具留痕」把 Agent 从"演示靠运气"升级为"失败有真相、成功可对账"。
